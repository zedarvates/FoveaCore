# 📐 FoveaEngine File Format Specification

FoveaEngine processes standard 3D Gaussian Splatting (3DGS) PLY files and serializes them into a highly optimized binary format (`.fovea`) for VRAM efficiency and fast loading.

---

## 1. Standard 3DGS PLY Format

FoveaEngine supports standard ASCII and Binary (little endian) PLY files generated by 3DGS training backends.

### PLY Header Structure
A standard 3DGS PLY file contains the following properties under the `vertex` element:

```text
ply
format binary_little_endian 1.0
element vertex 125842
property float x
property float y
property float z
property float nx
property float ny
property float nz
property float f_dc_0
property float f_dc_1
property float f_dc_2
property float opacity
property float scale_0
property float scale_1
property float scale_2
property float rot_0
property float rot_1
property float rot_2
property float rot_3
end_header
```

### Coordinate & Parameter Mappings

#### 1. Space Conventions
- **Source (OpenCV/COLMAP)**: X-right, Y-down, Z-forward.
- **Target (Godot)**: X-right, Y-up, Z-backward.
- **Conversion Math**:
  $$\begin{aligned}
  x_{godot} &= x_{ply} \\
  y_{godot} &= -y_{ply} \\
  z_{godot} &= -z_{ply}
  \end{aligned}$$

#### 2. Color (Spherical Harmonics Degree 0)
The standard colors are stored as Spherical Harmonics (SH) coefficients `f_dc_0, f_dc_1, f_dc_2` representing the raw diffuse color. They are mapped to standard RGB space $[0.0, 1.0]$ using:
$$RGB = f\_dc \times 0.28209479 + 0.5$$

#### 3. Scale & Rotation
- **Scale**: Stored as logarithmic scales `scale_0, scale_1, scale_2`. They are converted to linear scale using $\exp(scale_i)$.
- **Rotation**: Stored as unnormalized quaternions `rot_0` (w), `rot_1` (x), `rot_2` (y), `rot_3` (z). They must be normalized before construction of the covariance matrix.

---

## 2. Optimized Binary `.fovea` Format

The `.fovea` format is a custom container designed for direct GPU memory upload, skipping CPU parsing overhead. It integrates **Vector Quantization (VQ)** and **Spatial Quantization** to compress each splat down to exactly **16 bytes** (an 80% reduction from the ~76-byte CPU representation).

### 2.1 File Layout

A `.fovea` file consists of three contiguous sections:

```
┌────────────────────────────────────────────────────────┐
│ Header (48 bytes)                                      │
├────────────────────────────────────────────────────────┤
│ Covariance Codebook (K × 12 bytes)                     │
├────────────────────────────────────────────────────────┤
│ Packed Splat Data (N × 16 bytes)                       │
└────────────────────────────────────────────────────────┘
```

### 2.2 Header Structure (48 bytes)

| Offset (Bytes) | Type | Field | Description |
|---|---|---|---|
| 0 | `char[8]` | `magic` | Magic header bytes: `FOVEA_3D` |
| 8 | `uint16` | `version` | File format version (currently `2`) |
| 10 | `uint16` | `codebook_size` | Number of clusters in the codebook ($K$, max 1024) |
| 12 | `uint32` | `splat_count` | Total number of splats ($N$) |
| 16 | `float[3]` | `aabb_min` | Bounding box minimum coordinates (X, Y, Z) |
| 28 | `float[3]` | `aabb_max` | Bounding box maximum coordinates (X, Y, Z) |
| 40 | `uint8[8]` | `reserved` | Reserved bytes for future options (aligned) |

### 2.3 Covariance Codebook (K × 12 bytes)

Instead of storing individual 3D scale and quaternion rotations per splat, covariances are clustered using K-Means++ into $K$ centroids. Each codebook entry represents a packed 3D covariance descriptor:

- **Scale Vector**: 3 floats representing $(s_x, s_y, s_z)$ (or 3 half-floats if compressed further).
- **Rotation Quaternion**: Quaternions encoded in compact formats.

### 2.4 Packed Splat Data Layout (`FoveaPackedSplat` - 16 bytes)

Each splat is serialized as a 16-byte aligned struct:

```rust
#[repr(C, align(16))]
pub struct FoveaPackedSplat {
    pos_x: u16,        // 2 bytes: Quantized X coordinate
    pos_y: u16,        // 2 bytes: Quantized Y coordinate
    pos_z: u16,        // 2 bytes: Quantized Z coordinate
    norm_u: i8,        // 1 byte:  Octahedral normal parameter U
    norm_v: i8,        // 1 byte:  Octahedral normal parameter V
    color_index: u8,   // 1 byte:  Index in the 256-color palette
    padding1: u8,      // 1 byte:  Reserved/Alignment
    covar_index: u16,  // 2 bytes: Index in the Covariance Codebook (0 to K-1)
    opacity: u8,       // 1 byte:  Quantized opacity [0, 255] -> [0.0, 1.0]
    layer_id: u8,      // 1 byte:  Visual layer tag (BASE/SATURATION/LIGHT/SHADOW)
    dither_seed: u8,   // 1 byte:  Seed pattern for Floyd-Steinberg dithering
    padding2: u8,      // 1 byte:  Reserved/Alignment
}
```

### 2.5 Quantization Mathematics

#### Spatial Quantization (16-bit Local Grid)
Positions are mapped from the global AABB box boundaries to a local fixed-point grid:
$$pos\_quantized_i = \text{round}\left( 65535 \times \frac{pos_i - AABB\_min_i}{AABB\_max_i - AABB\_min_i} \right)$$

In shaders, the positions are restored back to floats using:
$$pos_i = AABB\_min_i + \left( \frac{pos\_quantized_i}{65535.0} \right) \times (AABB\_max_i - AABB\_min_i)$$

#### Color Quantization (8-bit Palette + Dithering)
RGB diffuse color is compressed using K-Means++ clustering to compile a 256-color palette (stored as a 16x16 texture in the shader). Error diffusion is applied using Floyd-Steinberg dithering:
$$\text{Error} = Color_{original} - Palette[Color\_index]$$
$$\text{Error} \text{ is diffused to neighboring splats with weights } \left[ \frac{7}{16}, \frac{3}{16}, \frac{5}{16}, \frac{1}{16} \right]$$
